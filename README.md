# kingyo_emu_cpp

金魚（和金）のシミュレータ。**泳ぎを物理で解いています**（アニメーションを描いてはいません）。
計算も描画もすべて C++、Emscripten で WASM にして走らせます。作りは
[suisou_emu_cpp](https://github.com/yomei-o/suisou_emu_cpp) と同じ ABI・同じハーネス。

## ▶ WASM デモ

### **https://yomei-o.github.io/kingyo_emu_cpp/wasmdist/kingyo_os/**

## 金魚とネオンテトラで変えたところ

**尾びれは体の進行波の続き。** ここが金魚らしさのほとんどです。体の中心線を伝わる波を
`s`（鼻先 0 〜 尾柄 1）で持ち、**尾びれは s > 1 の領域としてそのまま延長**しています。
波は s が大きいほど位相が遅れるので、**尾は体が振り終わってから遅れて返ってきます**。
尾柄に剛体の扇を貼ると、板を振っているようにしか見えません。

| | ネオンテトラ | 和金 |
|---|---|---|
| 体長 | 3cm | 8〜13cm |
| 体高 / 体長 | 0.27 | **0.36**（寸胴） |
| 巡航 | 1.5 体長/秒 | **0.8 体長/秒**（ゆったり漂う） |
| 旋回の角速度 | 3.4 rad/s | **1.7 rad/s**（体が大きくて曲がれない） |
| 曲がるときの湾曲 | 0.16 L | **0.55 L**（大きく弓なりになる） |
| 群れ | 分離・整列・結合 | **群れない**（避けるだけ） |
| 密度 | 0.8 匹/L | **0.04 匹/L**（1匹あたり25L） |
| ひれ | 小さい扇 | 背びれは**基底が長い**、胸びれで漕ぐ、尾は二叉で長い |

**胸びれで漕ぎます。** 金魚は止まるとき・後退するときに胸びれを細かく扇ぎます。
遊泳速度が巡航より遅いほど速く漕ぐようにしてあるので、ホバリングしているのが見えます。

## 写真を1枚のまま格子で曲げる

![model](model.png)

**魚まるごと1枚のスプライトを格子に貼り、格子を波で曲げています。**
出てくる絵は写真そのもので、こちらが計算するのは曲がり方だけです。

はじめは胴体を長方形に展開し、ひれを5枚切り出して別々に貼っていましたが、これは
**写真を分解してしまう**作りでした。頭の丸み・ひれの付き方・目の位置がそれぞれ別に
近似されるので、どこかが必ず嘘になります。1枚のまま曲げれば、頭も目も鱗もひれも写真のままです。

- 尾びれは `s > 1` の領域として体の波の続きで曲がる（**付け根に継ぎ目が無い**）
- 写真から測った胴の輪郭より外にある格子点を**ひれ**とみなし、扇の開閉・後ろへの流れ・
  横への煽ぎを足す。胸びれも腹びれも尻びれも、切り出さずに動く
- ひれの透け具合は**張り出しの量**から決める。写真の明るさから測ると、
  **黄色いひれは彩度が高いので「不透明」と出てしまう**（青が低いのは薄いからではない）
- 体は平面ではなく**断面が楕円の筒**。各点をカメラ側へ `厚み×√(1-t²)` 膨らませるので、
  斜めを向いても幅を持ったまま回る（平面のままだと紙が回っているように見える）
- 明るさと透け具合は**頂点で持って補間**する。面ごとに1つの値にすると格子の目が縞になる

`tools/mktex.cpp` が写真から `src/kingyo_tex.h` を作ります。これがあれば貼り、
無ければ手続きで作った素赤／更紗で描きます（`__has_include`）。

**輪郭は自動で拾います。** 手で制御点を測る作りだと、魚を替えるたびに測り直しになるので
（出目金もピンポンパールも同じ道具で通したい）、2段で分けています。

1. **魚と背景** — α があればそれを使い、無ければ四隅の色に近いものを背景とみなす
2. **胴体とひれ** — ひれは胴体より明るい（金魚の胴は濃い朱、ひれは淡い黄）。
   明るさのヒストグラムを**大津の判別分析**で2つに割り、暗いほうを胴体とする。
   しきい値を決め打ちにすると写真ごとに破綻するので、写真から決めさせる

そのうえで、列ごとに「いちばん長く続いた胴体の並び」を取ります。
**背びれ・尻びれの付け根では輪郭が体の内側に食い込む**ので（付け根は明るくて胴体から外れる）、
広い窓でならした線より内側に入った列はその線で置き換えます。
この輪郭は、貼るときに「どこからがひれか」を決めるのにも使います。

```sh
clang++ -O2 -std=c++17 -DSTBI_NO_SIMD -I. tools/mktex.cpp -o mktex
./mktex assets/kingyo_wakin.png src/kingyo_tex.h /tmp/sprite.png /tmp/outline.png KINGYO
#        入力写真                 出力ヘッダ        スプライト    輪郭の確認    記号
```

`/tmp/outline.png` に「元写真＋拾った輪郭」が出るので、うまく拾えているかはこれを見ます。

## モデルを見る

デモの **🔍 モデルを見る** ボタン（または `sim_set(20, 1)`）で、**1匹だけを画面中央に固定**して
泳がせます。体もひれも普通に動くので、形やひれを直すときに魚が画面に入るのを待たずに済みます。

```sh
EMSDK=~/emsdk ./build.sh kingyo_os      # -> wasmdist/kingyo_os/sim.js (+.wasm)
cd wasmdist && python3 -m http.server 8767

clang++ -O3 -std=c++17 -I. -Isrc src/kingyo_os.cpp -o kingyo
./kingyo 128 model.png 0.1 0 0 0.30 3.0 1
#        フレーム数 出力 [密度匹/L] [HUD] [餌フレーム] [画角m] [カメラ距離m] [1でモデル確認]
```

## 課題

- **泳ぎ方が硬い。** 実測の運動学（振幅の包絡 `y = 0.05 − 0.13x + 0.28x²`、
  波長 0.93 体長、旋回時のバンク、推進のたびの前後の押し）を一度入れてみましたが、
  見た目は良くならず戻しました（`e306fcd` の1つ前で試した内容）。
  実測どおりが本物らしく見えるとは限らない、というのが今の状態です。
  → 1つずつ入れて見比べるところから
- **個体差が無い。** 写真が1枚なので全部が同じ模様・同じ体型です。
  素赤／更紗の塗り分けや体型の変化をスプライトの上でどう出すか
- **正面を向くと厚みが出ない。** 2Dスプライトなので、真正面は横に引き伸ばして
  潰れを防いでいるだけです
- 写真の胸びれの下にある**影がそのまま入っている**
- 出目金・ピンポンパール（体型と目、尾の形を差し替える）。
  和金がきちんとできてから
